# 1-bufferpool-memory: most useful findings

1. innodb_buffer_pool_size (high): fully covered by what is collected already. Use the eBPF data-page-read off-CPU share as the gain bound and Innodb_buffer_pool_reads/trx as the predicted metric. Swap/PSI is the stop signal.
2. temptable_max_ram (medium, analytics): NOT collected. Add performance_schema.memory_summary_global_by_event_name 'memory/temptable/%' (physical_ram peak vs cap, physical_disk), plus TempTable_count_hit_max_ram where it exists. In 8.0, Created_tmp_disk_tables can miss TempTable overflow (bug #98741).
3. large_pages (low-medium, CPU-bound in-memory): NOT collected. Add perf dTLB-miss/page-walk cycles and /proc/meminfo HugePages_*. The page-walk share of mysqld cycles bounds the gain.
4. innodb_numa_interleave (only on multi-node hosts): NOT collected. Add the NUMA node count, per-node numastat (numa_miss/foreign) and per-node mysqld RSS. Swapping while another node has free memory is the strong signal.
5. innodb_old_blocks_time / _pct: add the made-young / not-young rates (MySQL I_S.INNODB_BUFFER_POOL_STATS PAGES_MADE_YOUNG(_RATE)/PAGES_NOT_MADE_YOUNG; MariaDB Innodb_buffer_pool_pages_made_young/_made_not_young). Combine them with the read counts of scan and point-lookup digests.
6. innodb_buffer_pool_instances: the CPU profile and eBPF latch share give the bound. The per-mutex breakdown (buf_pool_LRU_list_mutex, hash_table_locks) needs P_S wait/synch instruments, which are off by default.
7. innodb_change_buffer_max_size: irrelevant under modern defaults (change buffering none in MySQL 8.4+ and MariaDB 10.11; removed in MariaDB 11). If it is enabled, add the ibuf merge counters.
8. Temp-table/sort/join sizes (tmp_table_size, max_heap_table_size, sort_buffer_size, join_buffer_size): the status counters and digests (SUM_CREATED_TMP_DISK_TABLES, SUM_SORT_MERGE_PASSES, SUM_SELECT_FULL_JOIN) are already collected. Bound the gain by the time share of the spilling digests. Hash-join spill I/O in tmpdir is not attributed.
9. No measurable signal; validate only by experiment, or there is no performance effect: the dump/load trio (warm-up only; tuner runs skip it), chunk_size (ignored in MariaDB 10.11.12+/11.4.6+), memory-limit caps (connection_memory_limit, global_connection_memory_limit, max_session_mem_used), aria_used_for_temp_tables, and bulk_insert/read_buffer/read_rnd/join_buffer_space_limit.
10. DD caches (schema/tablespace_definition_cache, stored_program_cache) have no status counters. A data-dictionary/parse category in the CPU profile would be the only signal. MyRocks: rocksdb_block_cache_*_miss and rocksdb_stall_memtable_limit_* come in through the status deltas, but eBPF has no SST-read bucket.
