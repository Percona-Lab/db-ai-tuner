# 4-connections-observability-misc: notes

1. performance_schema is the only medium/high-impact performance knob in this chunk: its cost is already measured by the CPU profile's `performance_schema` category (3-5% typical, up to ~25% CPU on 2 vCPU). Cut instruments and consumers before turning it OFF, because the tuner needs it to observe.
2. Thread pool settings (oversubscribe, stall_limit, high_prio_*) currently have no signals collected. Add the Percona `Threadpool_*` status variables. Current docs list `Threadpool_requests_waiting_in_queue`, `Threadpool_requests_waiting_in_hp_queue`, `Threadpool_requests_starved_in_queue`, and `Threadpool_average_[hp_]queue_wait_us`; the last two are cnt/avg/min/max/dev strings that must be parsed. For MariaDB, add `INFORMATION_SCHEMA.THREAD_POOL_GROUPS`, `THREAD_POOL_STATS` (STALLS, THROTTLES, THREAD_CREATIONS_DUE_TO_STALL) and `THREAD_POOL_QUEUES` (QUEUEING_TIME_MICROSECONDS). Queue wait is the time quantity that bounds the possible gain.
3. Logging knobs (general_log, slow_query_log, long_query_time, log_slow_rate_limit) are bounded directly by P_S `file_summary_by_event_name` for `wait/io/file/sql/query_log` and `wait/io/file/sql/slow_log` (SUM_TIMER_WAIT, bytes). Those two rows are cheap to add. general_log ON should just be a hard configuration check.
4. Connection-path knobs (back_log, host_cache_size, skip_name_resolve, thread_cache_size) cannot matter when the benchmark uses persistent connections. Gate them on the `Connections` rate during the window. back_log needs OS `nstat TcpExtListenOverflows/TcpExtListenDrops` (not collected). DNS knobs need `performance_schema.host_cache` sampling and getnameinfo time (not collected).
5. Table caches: `Opened_tables` and `Opened_table_definitions` are collected. Also add `Table_open_cache_misses` and `Table_open_cache_overflows` explicitly. table_open_cache_instances needs the `wait/synch/mutex/sql/LOCK_table_cache` wait time, which requires that mutex instrument to be enabled.
6. Deadlocks: MySQL and Percona have no `Innodb_deadlocks` status. Use INNODB_METRICS `lock_deadlocks` on MySQL/Percona and `Innodb_deadlocks` on MariaDB. innodb_print_all_deadlocks matters only for diagnosis.
7. binlog_rows_query_log_events costs binlog bytes per trx. Measure it with P_S `wait/io/file/sql/binlog` bytes written (MariaDB: `Binlog_bytes_written`). The MariaDB analog binlog_annotate_row_events defaults to ON.
8. These have no measurable performance signal and are only functional limits: max_allowed_packet, thread_stack, performance_schema_max_digest_length (check for truncated DIGEST_TEXT), innodb_status_output, innodb_monitor_enable. Client error counts by code would catch the first two.
9. open_files_limit is indirect. Detect startup shrinking of table_open_cache/max_connections by comparing effective vs configured values, plus `Open_files` and `Opened_files`.
10. Some chunk defaults look like the tuner's bench config rather than server defaults: skip_name_resolve ON, host_cache_size 0, back_log 10000 for 9.7. Check before using them as a baseline.
